# Hybrid VSIX Package Registration Contract

This document prevents recurrence of the package-load failures found in Marketplace versions `1.0.47.0` and `1.0.48.0`, and the duplicate/stale View-menu state reported during the `1.0.49` line.

## Incident

On a new Visual Studio 2022 PC, the `1.0.47.0` VSIX extracted both of these files into the extension folder:

- `RawBufferVisualizer.VisualStudio.Vssdk.dll`
- `RawBufferVisualizer.VisualStudio.Vssdk.pkgdef`

The debugger visualizer host opened, but the docked ToolWindow package did not process the handoff. The user received:

```text
The docked Raw Buffer Visualizer did not acknowledge the image handoff.
```

The old build copied a `.pkgdef` generated by a separate VSSDK project into the hybrid VSIX. The local install script then wrote a developer-build `CodeBase` directly into the Visual Studio configuration registry. This made local installed-VSIX tests pass even though a clean Marketplace installation could not load the package.

`1.0.48.0` moved package ownership into the hybrid project and generated a correct installed-folder `CodeBase`. Local reinstall/runtime tests passed, but an external PC that updated from the failed release still showed the View command without opening the ToolWindow, and handoffs timed out. Microsoft documents that Visual Studio can discover a package's commands without loading the package, so menu visibility is not package-load evidence. Because `1.0.48` reused the failed VSPackage GUID, `1.0.49` assigned a new package identity while keeping the Marketplace extension identity stable.

Public Marketplace `1.0.49.0` is reported working on the affected Windows 10 PC after the extension was uninstalled and reinstalled. This is a clean-reinstall result only; it does not prove an in-place update. Source `1.0.50.0` retains the `1.0.49` VSPackage identity and uses `Menus.ctmenu` resource version 2 plus exact single-registration checks to prevent stale or duplicate View commands.

## Required ownership

There is one public hybrid extension owner:

```text
RawBufferVisualizer.VisualStudio.Extensibility
├─ Modern debugger visualizer providers
├─ RawBufferVisualizerPackage
├─ RawBufferVisualizerCommands.vsct
├─ PkgdefProjectOutputGroup
└─ RawBufferVisualizer.VisualStudio.Extensibility.vsix
```

`RawBufferVisualizer.VisualStudio.Vssdk` is a referenced ToolWindow/UI support library. It must not own or generate the Marketplace `.pkgdef`.

The source manifest must contain:

```xml
<Asset Type="Microsoft.VisualStudio.VsPackage"
       d:Source="Project"
       d:ProjectName="%CurrentProject%"
       Path="|%CurrentProject%;PkgdefProjectOutputGroup|" />
```

The generated VSIX must contain:

```text
RawBufferVisualizer.VisualStudio.Extensibility.pkgdef
RawBufferVisualizer.VisualStudio.Extensibility.dll
RawBufferVisualizer.VisualStudio.Vssdk.dll
```

The generated `.pkgdef` must contain:

```text
[$RootKey$\Packages\{1977574b-f107-465f-bfd1-5fc022907039}]
"Class"="RawBufferVisualizer.VisualStudio.Vssdk.RawBufferVisualizerPackage"
"CodeBase"="$PackageFolder$\RawBufferVisualizer.VisualStudio.Extensibility.dll"

[$RootKey$\Menus]
"{1977574b-f107-465f-bfd1-5fc022907039}"=", Menus.ctmenu, 2"
```

The package, menu, and ToolWindow registrations must each occur exactly once. It must not reference `RawBufferVisualizer.VisualStudio.Vssdk.dll` as the package `CodeBase`, and it must not contain retired Package GUID `{c15cc508-0fef-49bb-9478-4d2fdf9f87d2}`. The Marketplace extension ID remains `RawBufferVisualizer.34f8ad30-2f11-4c37-a9d4-00f3a8c1d29f`.

`Menus.ctmenu` version is a cache contract. Any future VSCT command or group change must increment `[ProvideMenuResource("Menus.ctmenu", N)]` and update the publish, install, repair, and Marketplace-update checks in the same change.

## Automated gates

Build the Marketplace payload through:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Publish-VisualStudioExtension.ps1 `
  -Configuration Release `
  -Framework net472 `
  -ViewerFramework net472 `
  -NoZip
```

The script fails if:

- `PkgdefProjectOutputGroup` is no longer used by the hybrid project;
- the generated manifest does not reference `RawBufferVisualizer.VisualStudio.Extensibility.pkgdef`;
- package, `Menus.ctmenu, 2`, or ToolWindow registrations are absent or occur more than once;
- `CodeBase` points to the VSSDK support library;
- the obsolete `RawBufferVisualizer.VisualStudio.Vssdk.pkgdef` appears in the VSIX;
- the retired `1.0.47`/`1.0.48` Package GUID appears in the generated registration;
- more than one main extension manifest is installed for a Visual Studio instance, or the legacy split `RawBufferVisualizer.VisualStudio.Vssdk` extension remains;
- the hybrid package references `Microsoft.VisualStudio.Threading` newer than `17.9.0.0`.

`Install-VisualStudioExtension.ps1` must never write package registration during a normal install. `-RepairRegistrationOnly` is an explicit recovery path and cannot be used as release evidence.

## Release verification

After installing the VSIX and restarting Visual Studio:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Test-VisualStudioMarketplaceUpdate.ps1 `
  -ExpectedVersion 1.0.50.0

powershell -ExecutionPolicy Bypass -File .\scripts\SmokeInstalledVsixNewFeatures.ps1 `
  -Scenario AutomaticVisionInspector `
  -Configuration Release `
  -NoBuild `
  -NoInstall

powershell -ExecutionPolicy Bypass -File .\scripts\SmokeInstalledVsixNewFeatures.ps1 `
  -Scenario MultiLibraryHybrid `
  -Configuration Release `
  -NoBuild `
  -NoInstall
```

The package is not publishable unless the runtime smoke proves all of the following:

- `RawBufferVisualizerPackage.InitializeAsync` ran;
- a handoff request reached an explicit ACK after the document opened; disappearance of the ready request alone is not success;
- a rejected handoff preserves and surfaces its rejection reason;
- the docked ToolWindow displayed the image;
- no `did not acknowledge the image handoff` error appeared;
- the View menu contains exactly one open command and one current-frame scan command;
- initialized OpenCvSharp/Emgu values and automatic camera-frame values open automatically, while registered Bitmap reaches the same docked list through its glyph.

Do not use the presence of a permanent `HKCU:\Software\Microsoft\VisualStudio\17.0_<id>_Config` key as the sole success criterion. Standard VSIX `.pkgdef` data is managed by Visual Studio's private configuration store and may not be visible there after Visual Studio exits. The installed payload check plus real runtime handoff smoke is authoritative.

## Clean-PC acceptance checklist

Run both paths. Passing only one path is insufficient:

- clean profile: install `1.0.50` directly;
- update profile: start from public Marketplace `1.0.49`, then update to the exact `1.0.50` candidate without uninstalling the extension.

1. Install or update to the exact Marketplace candidate VSIX without repair or `/ResetSkipPkgs`.
2. Close and reopen Visual Studio.
3. Run `Test-VisualStudioMarketplaceUpdate.ps1`.
4. Open the View menu and confirm exactly one `Raw Buffer Visualizer` and one `Raw Buffer Visualizer: Scan Current Frame` entry.
5. Open the ToolWindow and confirm it appears.
6. Debug the sample with the breakpoint after image construction. Invoke the registered Bitmap visualizer and confirm the image appears without a handoff timeout.
7. Enable `Auto Inspect on Break`; confirm initialized OpenCvSharp and Emgu CV Mats open automatically. Run **Scan Now** and confirm no duplicate rows.
8. Confirm Fit remains aspect-correct after resize and Manual zoom/pan preserves center and scale.
9. Record Visual Studio/Windows versions, VSIX SHA-256, result JSON, screenshots, `package.log`, and relevant `ActivityLog.xml`.

## Recovery boundary

`Repair-VisualStudioExtensionRegistration.ps1` remains available for stale developer installations and upgrades from older builds. It manually writes the installed hybrid DLL path and therefore proves only recovery, not Marketplace package correctness.

If a clean PC requires the repair script, or if the public-`1.0.49` update succeeds only after uninstall/reinstall, the `1.0.50` release gate is failed.
